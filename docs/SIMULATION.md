# 仿真运行时

仿真按“板卡运行时、统一引脚网络、模拟求解器”分层。板卡支持等级由 Profile 声明，缺少工具链或镜像时应明确报告不可用原因。

## 当前运行时边界

| 板卡/系列 | 主要执行方式 | 适合的支持层级 |
| --- | --- | --- |
| AVR（Uno、Nano、Mega、ATtiny 等） | 浏览器内 `avr8js` | 数字、固件 |
| RP2040/Pico | 浏览器内 `rp2040js` | 数字、固件 |
| ESP32 系列 | QEMU 或后端 Worker，按 Profile 选择 | 固件、数字、串口/协议 |
| STM32 系列 | 后端 Worker/QEMU 桥接，按 Profile 选择 | 编译、固件、数字 |
| Raspberry Pi | QEMU/Linux 桥接 | Linux 固件和外设桥接 |

具体机器名、架构和产物格式以 `BoardProfile.runtime` 及后端运行时注册表为准，不应从显示名称推断。

## 统一连接模型

- 组件通过 `PinInfo` 描述数字、模拟、电源和协议引脚。
- `PinManager` 负责引脚解析、别名、连线和协议角色，避免每个运行时重复实现连接规则。
- UART、I²C、SPI 等总线使用 Profile 的协议角色连接；跨板卡连接必须同时满足电压和引脚能力。
- GPIO 事件进入相应 MCU 或组件运行时，观测值再回到画布和逻辑分析视图。

## 数字与模拟

数字仿真处理 GPIO、PWM、串口和常见协议，适合验证固件逻辑和连线关系。包含电压、电阻、电容或其他模拟模型的网络会按需交给 ngspice-WASM 求解；数字和模拟结果通过统一状态层显示。

新增器件时，先补齐 PinInfo 和元数据，再决定是否需要模拟模型。仅有外观而没有模型的器件不应被标记为混合信号器件。

## 常见排障

- **编译按钮不可用**：检查板卡支持等级、`arduino-cli`/ESP-IDF 是否安装，以及后端健康检查。
- **QEMU 无法启动**：检查机器配置、QEMU 可执行文件和所需镜像；不要修改前端名称来绕过后端检查。
- **引脚连不上**：核对 Profile 的 canonical pin 名称、别名和 renderer 坐标，确认组件 PinInfo 使用同一命名。
- **协议没有响应**：确认 SDA/SCL 或 MOSI/MISO/SCK/CS 角色完整，且两端电压和支持能力匹配。
- **模拟结果异常**：先用数字模型隔离连线问题，再检查 ngspice-WASM 的节点、单位和模型参数。
